# ABM Personal Portfolio — Implementation Plan

## 0. Project Definition

**Project:** Abdul Basit Memon (ABM) Personal Portfolio  
**Domain:** `https://www.engrabm.com/`  
**Design direction:** Quiet Technical Garden / Editorial Minimalism  
**Primary feeling:** Personal, intelligent, restrained, experimental, human, memorable.

The website should feel like a carefully maintained personal corner of the internet rather than a conventional developer portfolio.

Core principle:

> Build around what ABM makes, learns, writes, researches, and explores.

Avoid generic portfolio patterns:
- No giant gradient hero
- No excessive glassmorphism
- No skill percentage bars
- No huge decorative 3D objects
- No testimonial walls
- No bloated dashboard-style layouts
- No excessive cards
- No animation for animation's sake

The interface should be mostly black text on white with generous whitespace, strong typography, thin separators, tiny interaction details, and occasional subtle motion.

---

# 1. Goals

## Primary Goals

- Create a premium, minimal personal portfolio for ABM.
- Make the site strongly recognizable without relying on loud branding.
- Present software projects as the main proof of work.
- Treat writings and notes as an evolving personal knowledge garden.
- Make the site fast, accessible, responsive, and easy to maintain.
- Establish a strong technical SEO foundation.
- Make the site's content understandable to search engines and AI/LLM agents.
- Keep the content architecture flexible enough to grow for years.

## Secondary Goals

- Make `/projects` useful as a real portfolio archive.
- Make `/writings` suitable for long-form technical/editorial content.
- Make `/notes` suitable for short, unfinished, raw ideas.
- Make the portfolio feel alive through restrained interactions rather than visual clutter.

# 3. Design System

## Colors

```txt
Background:       #FFFFFF
Primary text:     #111111
Secondary text:   #6B6B6B
Muted text:       #999999
Borders:          #E8E8E8
Hover background: #F6F6F6
```

Do not introduce a persistent colorful brand palette in v1.

Small contextual accents are allowed only where they add meaning.

## Typography

### Display

Large but not enormous.

Suggested:
- 48–72px desktop
- 36–48px tablet
- 32–40px mobile

### Body

- 16–18px
- line-height around 1.6–1.75

### Metadata

Use mono font:
- 12–14px
- uppercase or small labels
- subtle letter spacing

### Editorial text

Occasionally use serif typography for emphasis or writing pages.

## Borders

Use thin borders:

```css
border-color: #E8E8E8;
```

Avoid strong shadows.

## Radius

Use very small radius values:

```txt
2px–6px
```

Do not make everything pill-shaped.

# 18. Motion System

Motion should be restrained.

## Page entry

```txt
opacity: 0 → 1
translateY: 8px → 0
duration: 200–300ms
```

## Links

```txt
150–200ms
```

## Project hover

Small horizontal movement:

```txt
translateX: 0 → 4px
```

## Images

Very subtle:
- fade
- slight scale
- no dramatic parallax

## Respect reduced motion

Always respect:

```css
prefers-reduced-motion
```

Disable non-essential animations for users who request reduced motion.

# 19. Accessibility

Requirements:

- semantic HTML
- proper heading hierarchy
- keyboard navigation
- visible focus states
- accessible links
- sufficient text contrast
- image alt text
- reduced-motion support
- no information conveyed only through animation
- mobile tap targets large enough
- screen-reader friendly navigation

Avoid using divs as buttons.

---

# 20. Responsive Strategy

## Mobile first

Breakpoints can be approximately:

```txt
mobile: < 640
tablet: 640–1024
desktop: > 1024
```

Mobile should not simply be the desktop layout compressed.

On mobile:
- reduce display typography
- collapse nav
- keep generous whitespace, but reduce vertical excess
- convert project previews to inline previews
- preserve readable line lengths
- avoid hover-only interactions
- make every important interaction tap-friendly

# 36. Definition of Done

The website is ready for v1 when:

### Visual

- [ ] It feels intentional within the first 5 seconds.
- [ ] White space dominates the experience.
- [ ] Typography feels premium.
- [ ] There are no unnecessary visual effects.
- [ ] The site does not look like a generic AI portfolio.
- [ ] Desktop and mobile both feel designed rather than merely responsive.

### Content

- [ ] Most important projects are represented accurately.
- [ ] Project descriptions are clear.
- [ ] About page feels personal.
- [ ] Writings and Notes feel distinct.
- [ ] `/now` is useful.
- [ ] `/raw` feels native to the site.

### Technical

- [ ] No console errors.
- [ ] No broken navigation.
- [ ] All important pages are indexable.
- [ ] SEO metadata exists.
- [ ] Sitemap works.
- [ ] Robots file works.
- [ ] Structured data is valid.
- [ ] `llms.txt` is accessible.
- [ ] Site is responsive.
- [ ] Keyboard navigation works.
- [ ] Reduced motion works.

---

# 37. Final Quality Rule

Before adding any element, ask:

> Does this make the website more useful, more personal, or more memorable?

If the answer is no, remove it.

The portfolio should feel like:

**a person who builds things and thinks deeply about them**

not:

**a website trying to prove that the person is a developer.**

That distinction is the foundation of the entire design.
